# cfprotobufcmp

This module compares the Protobuf code `github.com/centrifugal/protocol` has
now (generated by [cfprotobuf](../../cfprotobuf)) with the code it had up to
v0.22, generated by [vtprotobuf](https://github.com/planetscale/vtprotobuf).

It is a module of its own so that `protocol` does not depend on vtprotobuf.
`go test ./...` in the repository root does not descend here, use
`make protobuf-compat` and `make protobuf-bench` there.

## What is in here

| File | What it is |
| --- | --- |
| `types.go` | The message structs of `client.pb.go` as of the migration, with everything but the type declarations removed. |
| `types_vtproto.go`, `raw.go` | The old code, unchanged apart from the package name. |
| `types_cfprotobuf.go` | cfprotobuf code for the same structs, generated with the `CF` suffix so that both sets of methods fit on one type. |
| `compat_test.go` | Tests and a fuzz target comparing the two on the same values and inputs. |
| `bench_test.go` | Benchmarks of both on the same messages. |
| `results/` | Raw benchmark output [cfprotobuf/BENCHMARKS.md](../../cfprotobuf/BENCHMARKS.md) is generated from. |

`types.go` is a snapshot: messages added to the protocol later are not part
of the comparison. `types_cfprotobuf.go` is regenerated with
`make protobuf-compat-update` when the generator changes.

## What is compared, and against what

There are two references, and they are used for different things.

**vtprotobuf, here.** It is what `protocol` used, so the bytes on the wire
must not change:

- encoding (`TestMarshalMatchesVTProtobuf`): 200 000 random messages of all
  43 types produce identical bytes, by every marshaling method;
- decoding of what encoders produce (`TestUnmarshalMatchesVTProtobuf_Encoded`):
  identical messages, field by field.

**`google.golang.org/protobuf`, in the `protocol` package**
(`protobuf_official_test.go`). It is the reference implementation of the
format, so it decides what is right on input which is *not* what an encoder
produces:

- encoding is byte for byte what it produces with deterministic marshaling;
- on random, damaged and fuzzed input (`FuzzProtobufMatchesOfficial`)
  generated code and the reference agree on whether the input is acceptable
  and on the message it holds.

That test cannot live here: it needs real registered message types, which are
the ones in `protocol`.

On damaged input vtprotobuf and the reference disagree in a number of ways,
listed in the [cfprotobuf README](../../cfprotobuf/README.md#differences-with-vtprotobuf),
and cfprotobuf sides with the reference. So `compareUnmarshal` here does not
demand equality on such input. It checks that the differences are of the
known kinds: cfprotobuf may reject what vtprotobuf accepts, the other way
round only happens for fields with an unexpected wire type, and when both
accept an input they decode it to the same message.

## Performance

The numbers are in
[cfprotobuf/BENCHMARKS.md](../../cfprotobuf/BENCHMARKS.md), which is
generated from the raw output in `results/`.

To add a machine, in the repository root:

```
make protobuf-bench
mv internal/cfprotobufcmp/bench.txt internal/cfprotobufcmp/results/<machine>.txt
make protobuf-bench-doc
```
